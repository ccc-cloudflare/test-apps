# Workers 還是 Linode？

> 同樣是 $5/月檔位，Cloudflare Workers 和 Linode VPS 都能把 Mini-Lang 專家放上網。差別不在費用，在省的是什麼錢、付出的是什麼功夫。

## 1. 兩者的本質差異

| | Cloudflare Workers | Linode VPS |
|---|---|---|
| 模型 | Serverless：上傳程式碼，Cloudflare 在邊緣節點跑 | 傳統虛擬機：租一整台 Linux，自己裝東西 |
| 計費 | 按請求數 + CPU 時間（只算「真的在算」的時間） | 按月固定，機器 24 小時開著就是你的 |
| CPU | 短暫佔用，上限 10ms（免費）/ 30s（付費），見 [cpu-limit.md](cpu-limit.md) | 1–4 核心完整歸你用，沒有每請求限制 |
| 常駐程式 | 不能（單次請求內執行完就結束） | 可以（跑 Python server、cron、任何東西） |
| 網路位置 | 全球邊緣節點 | 固定一台機器的位置（例：東京、新加坡） |

## 2. 費用

| | Workers | Linode |
|---|---|---|
| 免費檔 | 10 萬請求/天，CPU 10ms | — |
| 入門付費 | $5/月（含 1,000 萬請求） | Nanode 1GB：$5/月 |
| 這個應用實際用量 | 每次對話 1 個請求 | 1 台最小機器就夠 |

**兩者都是 $5/月檔位就能跑。** 真正的成本差異在維運時間，不在帳單。

## 3. Cloudflare Workers

### 優點

1. **維運成本趨近於零**：不用管 OS 更新、防火牆、SSH 安全、程式掛掉自動重啟。`wrangler deploy` 上去就完事。
2. **免費檔真的夠用**（在 CPU 問題解決的前提下）：個人用一天幾十次對話，10 萬請求/天用不到 1%。
3. **HTTPS、網域、CDN 自動處理**：`*.workers.dev` 送你憑證；Linode 要自己搞 nginx + Let's Encrypt。
4. **全球低延遲**：邊緣節點就近服務；Linode 台灣使用者要連東京/新加坡機房。
5. **沒有長期開著的攻擊面**：不怕忘記續約或機器被打掛。

### 缺點（都是這個專案真實會踩到的）

1. **CPU 10ms 硬上限**（免費）：長回答串流可能中途被砍。要嘛付 $5、要嘛做 [cpu-limit.md](cpu-limit.md) 的批次轉發優化。
2. **不能跑 Python**：`expert_server.py` 要改寫成 JS（`src/worker.js` 已經做了，但這是真實成本——以後規格改，等於要維護兩套實作）。
3. **檔案系統不存在**：提示詞、詞典要打包進部署，改了要重新 deploy，不像本機 server 改檔即生效（可選 KV 更新，見 README）。
4. **除錯比較間接**：log 要上 Cloudflare dashboard 或 `wrangler tail` 看。

## 4. Linode

### 優點

1. **就是現成的東西搬上去**：`expert_server.py` 幾乎不用改（金鑰照樣用環境變數），加個 nginx + systemd + certbot 就上線，**沒有第二套程式碼要維護**。
2. **沒有任何 CPU/時間限制**：串流八千 tokens、跑 check 工具幾十次，都無所謂。
3. **靈活**：同一台機器還能跑 mini-lm 的訓練腳本、排程任務、其他網站——Workers 只能做「請求→回應」。
4. **完整 root 權限**：想加資料庫、快取、監控都行。

### 缺點

1. **維運是你的責任**：安全更新、fail2ban、憑證續約、server 掛掉要自己發現自己重啟。
2. **沒有免費檔**：一個月 $5 起跳，一年 $60。
3. **單點、單位置**：機房網路出事服務就斷；Cloudflare 是分散的。
4. **固定 IP 曝露攻擊面**：要自己關好防火牆（`expert_server.py` 本來只聽 127.0.0.1，上線要改成公開監聽 + 設定）。

## 5. 怎麼選

| 你的情況 | 建議 |
|---|---|
| 只是想要「網路上開一個網頁就能用」，不想管伺服器 | **Workers**（付 $5 解決 CPU 限制，或先做批次優化留在免費檔試用） |
| 想保持「只有一份 Python 實作」、同一台機器還要跑別的實驗 | **Linode**：把 `expert_server.py` 原封不動丟上去，加 30 分鐘的 nginx 設定 |

以這個專案的特性：Workers 版已經自包含（clone 後 `npx wrangler deploy` 就能上線），維護成本極低；而 Linode 版省下的重複實作，代價是永續的系統管理。**如果沒有「同一台機器還要跑別的東西」的需求，選 Workers**——Mini-Lang 專案的哲學本來就是「方向數得完、維運越少越好」，Workers 符合這個味道。
